# 多轨协同音乐编辑系统结构设计报告（技术版）

## 1. 目标与问题定义

当前系统逐轨调用 ACE-Step，模型在生成第 (s) 条 stem 时看不到其他 stem 的生成状态，因此学到的是多个独立条件分布，而不是多轨联合分布。本方案目标是建立联合扩散编辑器：在同一个 diffusion step 中同时更新所有轨道，并让轨道之间交换局部信息、共享全曲结构，同时严格控制编辑区域和保持区域。

目标分布为：

\[
p(z_{1:S}\mid c, m),\quad z_{1:S}\in\mathbb{R}^{B\times S\times T\times C}
\]

其中 (c) 包含文本、歌词、BPM、调性、段落等条件，(m) 是轨道/时间编辑 mask。

## 2. 设计依据与改进边界

| 来源 | 可复用思想 | 本项目改造 |
|---|---|---|
| Two-Stream（NIPS 2014） | 将互补信息分到不同分支，再进行融合 | 将空间/运动分工改为全局音乐结构/局部轨道细节；由分类 late fusion 改为扩散中间层融合 |
| SlowFast | 低时间分辨率分支建模慢变化语义，高时间分辨率分支建模快速变化，并用 lateral connection 交互 | Slow 建模段落、和声、节拍、编配；Fast 建模音符、onset、音节和边界；加入 stem-aware 交互 |
| ACE-Step | DiT、VAE/latent、文本/歌词 cross-attention、repaint/SFT-stems | 保留原主干和条件接口，增加多轨 latent、跨轨注意力、同步去噪和 mask clamp |
| 本项目新增 | 无 | 多轨联合输出、编辑/保持约束、sync/harmony/mix/preserve 损失、局部编辑协议 |

## 3. 系统总览

```text
多轨音频/参考音频/编辑指令
          │
          ├─ VAE 或 ACE-Step 音频编码器 → Z:[B,S,T,C]
          ├─ 文本、歌词、BPM、调性、段落 → C_text/metadata
          └─ edit/preserve mask → M:[B,S,T,1]
                    │
        ┌───────────┴───────────┐
        │                       │
  Slow Global Branch      Fast Local Stem Branches
  T→T/r，较强语义容量        保持 T，高时间分辨率
  全局结构/和声/节拍          音符/onset/边界/音色
        │                       │
        └── Lateral Connections ─┘
                    │
             Cross-Stem Attention
                    │
             ACE-Step Text/Lyric CA
                    │
              每轨噪声预测 ε̂_s
                    │
       同步 diffusion 更新 + reference clamp
                    │
          多轨 latent → VAE decode → stems/mix
```

## 4. 输入与条件接口

### 4.1 多轨 latent

每条 stem 通过现有编码器得到 (z_s\in\mathbb{R}^{T\times C})，堆叠为 `[B,S,T,C]`。每个 token 加入 stem ID、时间位置、乐器角色和编辑状态 embedding：

\[
e_{s,t}=e_s^{stem}+e_t^{time}+e_s^{role}+e_{s,t}^{edit}
\]

建议第一版固定 (S=4)（vocals/drums/bass/other），后续用 `stem_present` mask 支持可变轨道数。

### 4.2 编辑 mask

`M=1` 表示保持参考，`M=0` 表示允许生成。mask 同时支持轨道级和时间级：例如只编辑 vocals/bass 的 42–58 秒，drums/other 全程保持。

### 4.3 条件信息

保留 ACE-Step 原有文本/歌词条件，并增加结构化条件：BPM、beat/downbeat、key/chord、section、track role、must_change、must_preserve。结构化条件可通过 embedding 后拼接到文本 encoder memory，或作为独立 cross-attention memory。

## 5. Slow Global Branch

### 5.1 结构

对时间轴下采样 (r=2\) 或 4：

\[
Z_{slow}=Downsample_t(Z)\in\mathbb{R}^{B\times S\times T/r\times C_s}
\]

保留 stem 维度，并通过 attention pooling 产生全局 memory (G\in\mathbb{R}^{B\times T/r\times C_g})。Slow Transformer 使用较大的时间感受野，负责段落、和声、BPM、整体动态和编配密度。

### 5.2 设计原则

- (r) 从 2 开始，避免丢失音乐节拍细节；
- Slow 分支通道数可与原 DiT 相当；
- 加入 beat/bar/section positional embedding；
- 可使用少量全局 token 压缩长歌曲上下文。

## 6. Fast Local Stem Branches

Fast 分支保持原始时间分辨率：

\[
Z_{fast}=Z\in\mathbb{R}^{B\times S\times T\times C_f}
\]

每条 stem 先做共享参数的 temporal self-attention，并使用 stem embedding 区分轨道。Fast 重点处理音符起止、鼓点 onset、人声音节、局部音色和编辑边界。为控制计算量，初始可取 (C_f=C/2)，而不是直接复制完整 ACE-Step 分支。

## 7. Cross-Stem Attention

对目标轨道 (s)，读取其他轨道 (j\neq s) 的同时间或局部窗口特征：

\[
H'_{s,t}=H_{s,t}+\mathrm{Attn}(q=H_{s,t},k/v=H_{j,t-\Delta:t+\Delta})
\]

加入 stem relation bias 和 attention mask，允许 vocals–drums、bass–drums、bass–piano 等关系学习不同权重。第一版采用局部时间窗口，避免 `[S*T]` 全连接 attention 的显存开销。

## 8. Lateral Connections

### 8.1 Slow→Fast

上采样 Slow 特征并注入 Fast：

\[
H_{fast}'=H_{fast}+g_{s\to f}(t)W_{s\to f}Up(H_{slow})
\]

它向局部编辑提供段落、和声、节拍和编配背景，是第一版必须实现的连接。

### 8.2 Fast→Slow

将 Fast 沿时间池化后反馈：

\[
H_{slow}'=H_{slow}+g_{f\to s}(t)W_{f\to s}Pool(H_{fast})
\]

它提供局部节奏和 onset 反馈。建议第二阶段再打开，以降低训练不稳定性。gate 由 diffusion timestep embedding 产生，高噪声阶段偏重全局结构，低噪声阶段增加细节融合。

## 9. ACE-Step DiT 融合位置

建议将原有 block 扩展为：

```text
Temporal Self-Attention
→ Cross-Stem Attention
→ Slow Global Cross-Attention
→ Slow/Fast Lateral Fusion
→ 原有 Text/Lyric Cross-Attention
→ AdaLN + MLP
```

原 ACE-Step 主干尽量复用；新增模块使用零初始化 residual gate，使初始网络近似原模型。

## 10. 联合扩散推理

初始化所有轨道的 noisy latent (Z^N)。每个 diffusion step：

1. 所有轨道同时进入 Slow/Fast/Cross-Stem DiT；
2. 一次前向得到所有轨道的 ε̂；
3. 使用调度器更新 (Z^{n-1})；
4. 对 `M=1` 的区域替换为参考 latent 的同噪声版本；
5. 进入下一步。

参考替换为：

\[
Z^{n-1}\leftarrow(1-M)\odot\hat Z^{n-1}+M\odot q(Z^{ref}_0,n-1)
\]

这继承 Multi-Track MusicLDM 的 inpainting/clamp 思路，并适配 ACE-Step repaint。

## 11. 训练目标与数据

基础扩散损失：

\[
L_{diff}=\sum_s\|\epsilon_s-\hat\epsilon_s\|_2^2
\]

可选辅助损失：`L_sync`（beat/onset）、`L_harmony`（chroma/HPCP/chord）、`L_mix`（stem sum 与 mix）、`L_preserve`（非编辑区域保持）。总损失为：

\[
L=L_{diff}+\lambda_1L_{sync}+\lambda_2L_{harmony}+\lambda_3L_{mix}+\lambda_4L_{preserve}
\]

训练样本从 MUSDB18 等多轨数据随机生成：随机选择编辑轨道、编辑区、可见轨道和保持轨道，并生成 T6/T7 任务的 `must_change/must_preserve` 条件。歌曲级隔离 train/dev/test，避免同歌片段泄漏。

## 12. 训练与落地阶段

**阶段 A：** 现有模型 + 多轨输入预处理 + mask/repaint，建立无重训 baseline。

**阶段 B：** 冻结 ACE-Step 主干，只训练 Multi-Stem Encoder、Cross-Stem Adapter、Slow 分支和 gate。

**阶段 C：** 解冻 DiT 中间层和输入/输出投影，低学习率联合微调；加入辅助协同损失。

**阶段 D：** 支持任意轨道补全、可变 stem 数、双向 lateral 和更长上下文。

## 13. 工具侧接口

请求增加：`input_stems`、`target_stems`、`edit_region`、`must_change`、`must_preserve`、`beat_grid`、`chords`。输出保持现有 `edited_mix + edited_stems`，并增加 `stem_sync_lag`、`lufs_delta`、`preserve_error` 等诊断字段。

## 14. 评测与验收

除单轨质量和 FAD 外，重点报告：跨轨 beat/onset P95、和声匹配、stem LUFS 偏差、mix 重构误差、非编辑区保持率、整体 MOS、编辑意图成功率和推理显存/时延。对 T7 多轨协同任务，不能只看单轨 FAD。

## 15. 关键风险

- Slow 下采样过大导致节拍和音符边界模糊；
- Cross-Stem 全连接导致显存平方增长；
- 辅助损失过强导致音质下降；
- 训练 mask 分布与真实编辑分布不一致；
- 只增加网络结构但推理仍逐轨运行，无法获得真正协同。

## 16. 推荐的最小可行版本

固定四轨，使用 `r=2` 的 Slow 分支、原分辨率 Fast 分支、局部 Cross-Stem Attention、Slow→Fast lateral、轨道/时间 mask 和同步 diffusion。冻结原 DiT，仅训练新增模块，先以 beat P95、HPCP 一致性、非编辑保持率和整体 MOS 验证结构收益。
