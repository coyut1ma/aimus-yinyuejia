# 多轨协同音乐编辑系统结构设计报告（通俗版）

## 1. 我们要解决什么问题

现在系统是“一条轨道调用一次模型”。例如先单独改人声，再单独改贝斯。这样每一次编辑都像只听自己这一轨，模型不知道其他轨道正在发生什么，所以最后可能出现节拍不齐、和弦不合、音量不平衡。

新的目标是：所有轨道一起进入模型，在每一个生成步骤中互相参考，同时只改用户指定的部分。

## 2. 整体结构

```text
多条轨道的 latent 表示
        │
        ├─ Slow 分支：看全局结构
        │
        ├─ Fast 分支：看局部细节
        │
        ├─ 跨轨注意力：轨道之间互相参考
        │
        ├─ 分支连接：把整体信息传给细节，也可把细节反馈给整体
        │
        └─ ACE-Step DiT：同时生成所有轨道
```

这里的“latent”可以理解为模型处理音频时使用的压缩特征，不是直接的波形。

## 3. 多轨输入是什么样的

假设有 vocals、drums、bass、other 四条轨道。每一条轨道先被 ACE-Step 的音频编码器转换成一串随时间变化的特征，然后堆成：

```text
[批次大小，轨道数，时间长度，每个时间点的特征数]
```

模型还需要知道每个特征属于哪条轨道、处于什么时间、是编辑区还是保持区。因此要额外加入：

- 轨道标识：这是人声、鼓还是贝斯；
- 时间位置：它在歌曲的什么时间；
- 音乐角色：节奏、低频、旋律或和声；
- 编辑状态：这里允许修改，还是必须保留。

## 4. Slow 分支：负责全曲结构

Slow 分支会把时间信息压缩。例如原来每个很小的时间点都有一个特征，Slow 分支把相邻的一些时间点合并成一个更概括的特征。

这样它不会过分纠结某个瞬间的音符，而能看到更长的音乐范围，学习：

- 现在是主歌还是副歌；
- 整首歌的速度和节拍；
- 当前和弦进行；
- 整体情绪和动态；
- 这一段的编配是否应该变密或变疏。

它的作用是告诉模型：

> 这段局部编辑必须符合整首歌的大方向。

Slow 分支的“低时间分辨率、看更长范围”来自 SlowFast 论文。我们把视频中的慢变化语义改成了音乐中的段落、和声和编配信息。

## 5. Fast 分支：负责局部细节

Fast 分支保留更密集的时间信息，因此可以看清很短的变化：

- 鼓点到底落在哪一刻；
- 人声某个字从哪里开始；
- 贝斯某个音符什么时候结束；
- 编辑区边界是否突然断开；
- 某个音符和瞬态的音色是否自然。

它的作用是告诉模型：

> 在允许修改的这几秒里，具体的音符、节奏和边界应该怎么生成。

Fast 分支的“高时间分辨率、捕捉快速变化”也来自 SlowFast 论文，但我们把视频运动改成了音乐中的 onset、音符和局部瞬态。

## 6. 为什么需要跨轨注意力

Slow 和 Fast 只解决了“看整体”和“看细节”，还不能自动解决轨道之间的关系。因此还要增加跨轨注意力。

它允许：

- 人声参考鼓的节拍；
- 贝斯参考鼓的律动；
- 贝斯参考钢琴或吉他的和声；
- 伴奏参考人声的旋律和句法。

例如模型生成贝斯时，不再只看贝斯自己的特征，而是同时读取鼓、人声和其他伴奏在附近时间范围内的特征。

这部分是针对多轨音乐新增的设计，核心目的就是让轨道真正互相参考。

## 7. 分支之间如何联系

### 7.1 Slow → Fast

Slow 分支把段落、和声、节拍和整体情绪传给 Fast 分支。这样 Fast 在修改局部音符时不会脱离整首歌。

这是最重要、也是第一版最应该实现的连接。

### 7.2 Fast → Slow

Fast 分支可以把局部的鼓点密度、音符变化和边界情况反馈给 Slow 分支，让全局判断知道局部发生了什么。

但双向连接更复杂，第一版可以先只做 Slow → Fast，等基础效果稳定后再加入 Fast → Slow。

SlowFast 论文的启发在于：不同分支不应该只在最后才合并，而应该在网络中间多次交换信息。我们将这个连接改造成适合扩散生成的特征交换。

## 8. ACE-Step 在哪里发挥作用

原来的 ACE-Step DiT 仍然负责主要的音频生成能力，包括：

- 文本和歌词控制；
- 扩散去噪；
- 音频 latent 处理；
- 最后的音频解码。

我们不是完全替换 ACE-Step，而是在它的中间层加入：

```text
轨道内部的时间处理
→ 轨道之间互相参考
→ 读取 Slow 的全局信息
→ 读取文本和歌词
→ 输出每条轨道的预测结果
```

这样原有模型的音质能力可以尽量保留，新增部分专门学习多轨协同。

## 9. 局部编辑如何实现

系统需要给每条轨道、每个时间点标记两种状态：

- `允许生成`：用户希望修改的部分；
- `必须保持`：原始内容不能改变的部分。

例如：

```text
42–58 秒：编辑 vocals 和 bass
42–58 秒：drums 和 other 作为参考并保持
其他时间：所有轨道保持
```

在每一步生成后，系统都会把“必须保持”的部分重新换回原始内容的对应特征。这样模型不能因为修改人声，就顺便破坏鼓和其他伴奏。

这种“每一步都固定未编辑区域”的做法借鉴了 Multi-Track MusicLDM 的 latent mask 和 inpainting 思路，并与 ACE-Step 的 repaint 机制结合。

## 10. 为什么所有轨道必须同时生成

如果仍然是：

```text
先生成 vocals
再生成 bass
最后生成 drums
```

那么跨轨参考仍然是不完整的。

新的流程是：

```text
同一个生成步骤：同时预测 vocals、drums、bass、other
下一步：同时更新它们
```

这样每条轨道在每一个阶段都能看到其他轨道当前的状态，跨轨关系才会真正参与生成。

## 11. 训练时需要让模型学什么

模型除了学习“音频应该长什么样”，还要学习：

- 各轨节拍是否对齐；
- 各轨和声是否一致；
- 多条轨道相加后是否像合理的混音；
- 未编辑区域是否保持不变。

因此训练数据需要随机模拟各种任务：

- 只编辑一条轨道；
- 同时编辑两条轨道；
- 给定鼓和贝斯生成钢琴；
- 只编辑某个时间片段；
- 保留部分轨道、补全缺失轨道。

如果训练时每条轨道仍然独立处理，模型不会自动学会协同。

## 12. 推荐的实施顺序

### 第一步：先做不改主模型的测试

使用现有 ACE-Step 加上多轨 mask、参考音频和 repaint，先建立基线，确认任务和评测方法。

### 第二步：只训练新增部分

冻结原有 ACE-Step，只训练：

- 多轨音频编码器；
- 跨轨注意力；
- Slow 分支；
- 分支连接的控制参数。

这样不需要从零训练整个模型。

### 第三步：联合微调 ACE-Step

如果第二步有效，再解冻 DiT 的部分中间层，让原模型和新增结构一起适应多轨协同任务。

## 13. 这个结构对工具的直接收益

对于“只改一段人声”的任务：

- Fast 负责字、音符和边界；
- Slow 保证仍处于正确的歌曲段落；
- Cross-Stem Attention 让人声参考伴奏；
- mask 保证其他轨道和非编辑区不被破坏。

对于“同时改人声和贝斯”的任务：

- 两条轨道在同一个生成过程中同步更新；
- 人声和贝斯可以互相参考；
- drums 和其他伴奏提供节拍、和声和整体结构；
- 最终输出的多轨更容易直接混音。

## 14. 一句话总结

```text
Slow 决定“这一段整体应该是什么样”；
Fast 决定“这一段具体的音符和细节怎么改”；
Cross-Stem Attention 让轨道彼此参考；
同步 diffusion 保证它们一起变化；
编辑 mask 保证只改用户指定的地方。
```

这就是为什么该结构适合你们的多轨局部编辑工具：它同时兼顾全曲一致性、局部精细编辑、跨轨同步和未编辑区域保持。
